Name the platform you are standing on.

WordPress.com is a hosted service; self-hosted WordPress uses software on hosting you choose. This roadmap is useful for both, but blogguerz currently needs a calm WordPress.com-first pass: use the tools available, understand the tradeoffs, and do not summon a migration just because a tutorial got loud.

00

Foundation

Stabilize the house

No building on errors

Before archive dreams, make the public homepage reliable and leave yourself a rollback path. A blog can be messy; its entry point should not be broken.

Exit ticket The public homepage has no visible error, baseline screenshots exist, and you know exactly how to undo the last structural change.
01

Structure

Build the archive structure

Big doors, small cross-links

Categories are durable doors. Tags are smaller cross-links. The job is to make a growing archive browsable—not to create an archaeological disaster zone.

A useful starting category shape
essays
web dev
music / DJ
stream logs
life admin
racquelle saga
mutual aid

Use only categories that will still make sense after many more posts. Keep the set small enough to remember.

Exit ticket A stranger can browse by subject without knowing your exact titles or dates, and no category is removed before its posts have a clear destination.
02

Structure

Make navigation obvious

Answer the first three questions

A first-time visitor should quickly know: where am I, what is this, and where else can I go?

Small, sufficient primary navigation
Home · About · Archive · guerz.lol

Keep Legacy Journal and RSS available in a footer or sidebar unless they truly belong in your primary route.

Exit ticket A visitor understands the blog’s purpose in under ten seconds and can reach the rest of your work without being verbally guided through the interface.
03

Publish

Install the right rail

Navigation engine, not clutter shelf

The layout upgrade: a desktop sidebar that helps people roam the archive, then stacks below the feed on smaller screens.

Suggested sidebar order
search
browse by category
calendar
monthly archive
tags
legacy journal

Categories lead broad browsing. Calendar supports a dated journal. Tags stay lower because they are supporting metadata, not the whole navigation system.

Exit ticket Posts remain readable and a visitor can reach an older subject, month, tag, or search result in a couple of intentional clicks.
04

Publish

Standardize posts without sanding off the personality

Patterns, not a content factory

Repeatable post blocks reduce formatting friction. They should make publishing faster while leaving room for the journal voice to breathe.

Unsynced pattern kit
blogguerz post footer
blogguerz divider
optional link roll
filed-under / tagged-with line
previous / next post

Use unsynced patterns when changing a new post should not rewrite every old entry.

Exit ticket Publishing a new entry feels repeatable, quick, and recognizably blogguerz—not like filling out a corporate form.
05

Care & discovery

Make it findable, resilient, and welcoming

The public pass

The editor is not the website. Review the public URL like someone who has never met you, using a private window, a phone, a keyboard, and ordinary patience.

Exit ticket The site works for a new visitor, shared links are understandable, recovery is documented, and you know the next tiny care date.

Battle test register

Before you call it published.

The purpose is not to become a security engineer overnight. It is to discover predictable breakage before visitors do.

Parked · not today

Useful future work that does not get to hijack the quest.

  • Self-hosted WordPress migration
  • Paid hosting changes
  • Plugin hunting
  • Child themes, custom PHP, or custom block-theme work
  • Re-categorizing every post in one session

Unlock conditions

  • A specific missing capability requires it
  • You can name the exact pain point, not merely “WordPress feels limited”
  • The current navigation, archive, post pattern, and public tests have shipped
